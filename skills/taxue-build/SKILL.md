# taxue-build：固化流程 + 工具化

| 把反复出现的问题变成可复用的工具。

你的任务：帮用户把一次性的解决方案，沉淀为可复用的流程、模板、工具。

--------

## 核心原则

1. **复用优先**：如果一件事做了第二遍，就该固化
2. **最小可用**：先做 60 分能用的，再迭代到 90 分
3. **文档即工具**：没有文档的工具等于不存在

--------

## 什么时候触发

- 用户说「固化」「做成工具」「下次直接用」
- 同一个问题被问了第二次以上
- 用户说「这个流程很好，能不能保存下来」

--------

## 三步固化法

### Step 1：识别可固化的模式

问自己：
- 这个解决方案的核心逻辑是什么？
- 哪些步骤是固定的，哪些是变化的？
- 下次遇到类似问题，能直接复用吗？

### Step 2：选择固化形式

| 形式 | 适用场景 | 示例 |
|------|----------|------|
| 模板 | 固定结构的输出 | 简历模板、邮件模板 |
| 清单 | 固定步骤的流程 | 发布前检查清单 |
| 脚本 | 可自动化的操作 | 数据抓取脚本 |
| 决策树 | 固定逻辑的判断 | 选型决策树 |
| 知识库 | 可复用的信息 | FAQ、案例库 |

### Step 3：编写文档

每个固化工具必须包含：
1. **名称**：一句话说明是什么
2. **触发条件**：什么时候用
3. **输入**：需要什么信息
4. **步骤**：怎么做
5. **输出**：产出什么
6. **示例**：一个具体例子

--------

## 固化流程

### 流程模板
```markdown
# {流程名称}

## 触发条件
- {什么时候用}

## 输入
- {需要什么信息}

## 步骤
1. {步骤 1}
2. {步骤 2}
3. {步骤 3}

## 输出
- {产出什么}

## 示例
{一个具体例子}
```

### 清单模板
```markdown
# {清单名称}

## 检查项
- [ ] {检查项 1}
- [ ] {检查项 2}
- [ ] {检查项 3}

## 通过标准
- {怎么算通过}
```

### 决策树模板
```markdown
# {决策名称}

## 决策逻辑
- 如果 {条件 A} → {选择 A}
- 如果 {条件 B} → {选择 B}
- 如果 {条件 C} → {选择 C}

## 默认选择
- {没有明确条件时的默认选择}
```

## 工具化

### 什么时候工具化
- 固化流程被用了 3 次以上
- 用户说「能不能自动做」
- 流程可以完全自动化

### 工具化形式
| 形式 | 适用场景 | 实现方式 |
|------|----------|----------|
| 脚本 | 可自动化的操作 | Python/Bash 脚本 |
| 模板 | 固定结构的输出 | Markdown 模板 |
| 配置 | 可复用的参数 | JSON/YAML 配置 |

--------

## 输出前质量门（强制自查）

1. 有没有给一个今天能做的验证动作？没有 → 补一个。
2. 有没有把「可能」写成「一定」？有 → 改成「待验证」。
3. 有没有只站一个立场？有 → 补一个反方视角。
4. 有没有用「综合来看」「各方面」等模糊词？有 → 具体化。

任一不通过，修正后再输出。

--------

## 反模式声明

### 失败 1：为一次性的事造工具
一件事只做过一遍就急着固化，最后工具比问题还多，维护成本超过收益。
**纠正**：复用优先——**做了第二遍才固化**。第一遍是探索，第二遍才是模式。

### 失败 2：一次做到 90 分
想在设计阶段穷尽所有分支和边界，工具始终发不出来。
**纠正**：先交 60 分能用的版本，用起来再迭代。没被使用过的工具无法验证。

### 失败 3：给工具不给用法
交了模板、脚本、清单，却没说什么时候用、输入是什么、产出长什么样。
**纠正**：文档即工具——名称 / 触发条件 / 输入 / 步骤 / 输出 / 示例六项缺一不可，缺一项等于没交付。

--------

## DO NOT

- 问题还没理清、还在纠结 → 先 `solve`
- 学习方法本身 → `learn`
- 职业 / 内容 / 行业等专门分析 → 走对应分支（build 只固化流程，不做分析）

--------

## 共享规则与纪律

本技能继承 `../taxue/references/shared-rules.md` 的通用纪律，冲突时以它为准：**结果优先**（先交付立场与可验证动作，过程只在改变质量时写入）、**证据来源**（结论必须可追到来源，禁止无源断言）、语言与通用 DO NOT。

--------

## Outcome Contract

- **产出**：一个可复用的工具（模板 / 清单 / 脚本 / 决策树 / 知识库）+ 六项文档
- **做完的标准**：文档六项齐全，且用户能照着自己的工具用一遍
- **不做的事**：不做分析（走对应分支），不替用户执行流程本身
