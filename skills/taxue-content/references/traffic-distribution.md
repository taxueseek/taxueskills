## 课题 5：分发节奏——变量控制

### 分发变量矩阵

| 变量 | 可选项 | 测试方法 |
|------|--------|---------|
| 发布时间 | 早7-9/中12-14/晚20-22 | 固定内容类型，变换时间，记录数据 |
| 发布频率 | 日更/隔日/周更 | 固定质量，变换频率 |
| 平台组合 | 公众号+小红书+抖音/X | 同一内容适配不同平台 |
| 内容形式 | 图文/短视频/长文 | 同一选题尝试不同形式 |

### 分发节奏实验法

1. **选定一个变量**（如发布时间）
2. **固定其他所有变量**（内容类型、平台、形式不变）
3. **连续发布 7 次**，每次只变一个变量
4. **记录每次的数据**（阅读量、互动率、涨粉数）
5. **找到最优值**，锁定为默认设置

### 内容日历模板

```markdown
## {月份} 内容日历

| 日期 | 选题 | 形式 | 平台 | 发布时间 | 数据 |
|------|------|------|------|---------|------|
| 1/1 | {选题} | 图文 | 公众号 | 20:00 | - |
| 1/3 | {选题} | 短视频 | 抖音 | 12:00 | - |
| 1/5 | {选题} | 图文 | 小红书 | 20:00 | - |
```

### 素材库联动：内容日历从素材库生成

```
1. 从原子库按 type 分组（投资/认知/其他）
2. 按 tags 匹配当前热点方向
3. 从金句库选取开篇钩子，快速生成标题草案
4. 输出到内容日历
```

## 课题 6：平台机制——系统建模

### 平台机制速查

以下表格只用于生成待验证假设，不作为当前算法事实。平台机制会变化；用户问「为什么没推荐」「是否限流」或输出依赖算法判断时，必须联网核验平台官方说明并标日期，无法核验就用账号内实验验证，不宣称算法确定如此。

| 平台 | 核心指标 | 分发逻辑 | 内容偏好 |
|------|---------|---------|---------|
| 小红书 | 点击率+收藏率 | 标签匹配+互动加权 | 实用干货、清单、经验分享 |
| 抖音 | 完播率+互动率 | 流量池递进+标签匹配 | 强节奏、前3秒钩子 |
| 公众号 | 打开率+分享率 | 社交分发+订阅推送 | 深度观点、长逻辑链 |
| X/推特 | 转发率+回复率 | 社交关系+话题热度 | 锐利观点、thread |
| 知乎 | 赞同率+收藏率 | 问题匹配+质量权重 | 深度分析、干货 |
| B站 | 完播率+互动率 | 搜索+推荐双驱动 | 教程、深度内容 |

### 多平台分发策略

同一选题适配不同平台的核心动作：

1. **拆解核心**：提取「核心观点 + 关键论据 + 数据/案例」
2. **平台适配**：根据平台偏好调整形式和长度
3. **差异发布**：不要完全一样的内容全平台发

| 选题 | 公众号 | 小红书 | 抖音 | X/推特 |
|------|--------|--------|------|--------|
| 投资方法论 | 深度长文 | 清单体图文 | 60 秒口播 | Thread 拆解 |
| 案例分析 | 完整分析 | 关键结论+数据 | 故事化讲述 | 一句话判断+链接 |
| 工具推荐 | 详细评测 | 对比清单 | 30 秒演示 | 一句话推荐+截图 |

## 流量复盘模板

每篇内容发布后 7 天，做一次复盘：

```markdown
## 流量复盘：{内容标题}
- 发布日期：{YYYY-MM-DD}
- 平台：{平台列表}

### 数据
| 平台 | 阅读量 | 互动率 | 涨粉 | 转化率 |
|------|--------|--------|------|--------|
| {平台} | {数} | {数} | {数} | {数} |

### 归因
- 为什么高/低？
- 哪个环节贡献最大？
- 哪个环节拖了后腿？

### 下一步
- 保留什么？
- 改什么？
- 放弃什么？
```

### 工作站联动：数据追踪脚本

素材库中已有数据追踪脚本，可以拉取真实阅读数据做复盘：

```
踏雪素材库/scripts/
├── fetch_stats.py          — 抓取公众号文章数据
├── fetch_read_count.py     — 抓取单篇阅读量
├── auto_fetch_stats.py     — 自动批量抓取
└── test_stats.py           — 测试脚本
```

**复盘时执行**：

```bash
# 抓取最新的文章统计数据
python3 踏雪素材库/scripts/fetch_stats.py

# 抓取特定文章的阅读量
python3 踏雪素材库/scripts/fetch_read_count.py --article "{文章标题}"
```

**公众号历史数据参考**：

```
踏雪素材库/05_核心资产库/公众号归档/分析/
├── 高阅读量Top50.md          — 历史最高 50 篇，可做对标基准
├── 深度选题挖掘.md            — 系列内容的累计阅读量
├── 重复主题归纳.md            — 同一主题多次发布的效果对比
├── 文风演变与发文时间分析.md — 发布时间与阅读量的相关性
└── 未兑现承诺与被忽视选题.md — 规划了但没做的选题（反面参考）
```

复盘时将自己的数据与历史基准对比：
- 阅读量是否达到同分类的 Top50 中位数？
- 互动率是否高于同类文章的平均水平？
- 如果低于基准，六环节中哪个环节最可能是瓶颈？

## 反模式声明

### 反模式 1：流量焦虑替代思考
每天盯着数据，频繁换方向，但从不深挖一个选题。
**纠正**：流量是结果指标，不是过程指标。过程指标是「你的内容质量有没有提升」。

### 反模式 2：盲目追热点
什么火写什么，但没有自己的判断和立场。
**纠正**：热点是素材，不是选题。选题是你用独特视角解读热点的能力。

### 反模式 3：完美主义瘫痪
总觉得内容不够好，不敢发。
**纠正**：80 分发布 > 100 分不发。迭代只能在发布后进行。

### 反模式 4：忽视平台机制
同一内容全平台发，不做适配。
**纠正**：每个平台是一台不同的机器，需要不同的燃料。

### 反模式 5：数据迷信
只看阅读量，不看内容质量和读者质量。
**纠正**：1000 个精准读者 > 10000 个路人。

### 反模式 6：拿无来源基准制造确定性
把「行业平均」或反推值当成事实，进而过早锁定唯一根因。
**纠正**：优先做账号内纵向对比；外部基准附来源和口径；不能确认就标推断，用单变量实验区分原因。

## 与现有 skill 的协作

本 skill 和现有工作站是互补关系，不是替代：

| 场景 | 用哪个 |
|------|--------|
| 需要完整创作流程（标题→开头→正文→质量门） | `tx-create` |
| 需要内容诊断（五维分析） | `content` |
| 需要流量系统诊断（六环节） | `taxue-traffic`（本 skill） |
| 需要素材检索和注入 | `taxue-material` |
| 需要素材库管理 | `taxue-material` 的管理操作 |
| 需要风格润色 | `content-refiner` |

### 协作流程示例

```
用户想做一篇有流量的文章：

1. /taxue-traffic → 选题诊断（联动：主题地图 + 内容单元库 + 原子库）
2. /tx-create → 标题生成 + 开头优化 + 正文创作
3. /taxue-traffic → 分发节奏 + 平台适配（联动：平台风格规范）
4. 发布 → 素材库 scripts/fetch_stats.py 抓取数据
5. 发布 7 天后 → /taxue-traffic 流量复盘（联动：高阅读量 Top50 对标）
```
