# 开头模式库

## 核心原则

开头解决的是前三秒的问题。读者不关心你想说什么，他只关心「这跟我有什么关系」。

黄金法则：读完开头，读者会不会想「然后呢？」

## 七大开头模式

### 1. 冲突开头
结构：先说一个反直觉的事实或判断
示例：「所有人都告诉你 X，但我花了 Y 年发现他们都错了」
适用：观点输出、认知颠覆类内容

### 2. 故事开头
结构：一个具体的场景，有时间、地点、细节
示例：「那天下午 3 点，我盯着账户看了 10 分钟，然后做了一个决定」
适用：经验分享、案例复盘类内容

### 3. 结论开头
结构：直接给核心判断，不铺垫
示例：「关于 XXX，90% 的人都理解错了」
适用：观点犀利、有明确立场的内容

### 4. 提问开头
结构：一个问题让读者代入思考
示例：「你有没有想过，为什么 X 总是 Y？」
适用：引导思考、引发共鸣的内容

### 5. 数据开头
结构：用数字制造冲击
示例：「X 天，Y 次实验，Z% 的失败率——这是我做 XX 的全部数据」
适用：实验型、研究型内容

### 6. 场景开头
结构：描述一个读者熟悉的场景
示例：「打开手机，看到又跌了 2%，你会怎么办？」
适用：引发共鸣、带入感强的内容

### 7. 引用开头
结构：引用一句话，然后给出你的解读
示例：「查理·芒格说过一句话，我花了 5 年才真正理解……」
适用：深度思考、知识解读类内容

## 开头检测清单

写完开头后，逐项检查：

- [ ] 第一句话有没有制造好奇心或冲突？
- [ ] 前三行能不能让读者停下来？
- [ ] 有没有具体的时间/地点/数字/细节？
- [ ] 有没有废话可以删掉？（开头每个字都必须有存在的理由）
- [ ] 读完开头，读者会不会想「然后呢？」
- [ ] 开头和标题有没有呼应？（不是一回事，但方向一致）

## 平台适配

| 平台 | 开头要求 | 注意事项 |
|------|---------|---------|
| 小红书 | 1-2 行必须钩住 | 移动端阅读，前三行决定生死 |
| 抖音 | 前 3 秒必须出声 | 视频开头需要强钩子 |
| 公众号 | 前一段制造悬念 | 可以稍长，但必须有节奏 |
| X/推文 | 第一句话就是钩子 | 信息流极快，没有第二次机会 |
| 知乎 | 直接亮观点 | 知乎读者有耐心，但厌恶废话 |

## 开头禁区

| 禁区 | 示例 | 为什么不行 |
|------|------|----------|
| 背景铺垫 | 「在当今社会，随着 XX 的发展……」 | 废话，读者已经滑走了 |
| 自我谦虚 | 「我不是专家，只是分享一下……」 | 削弱可信度 |
| 正确废话 | 「XX 是一个很重要的话题」 | 等于没说 |
| 过度铺垫 | 用三段话才进入正题 | 读者等不了 |
| 和标题脱节 | 标题说 A，开头讲 B | 读者被骗进来的感觉 |
