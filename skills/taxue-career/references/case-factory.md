# 案例工厂

> 雇主买的是结果。你做过的事是原材料，案例才是能卖的商品。

**先重定义问题。** 「我该讲什么故事」问错了。真问题：面试官在什么场景、出于什么需要，要拿你交付过的结果当证据。FDE 行业把这个叫 RaaS——Result as a Service，交付的是结果而非活动量。求职同理：一段经历要卖的，是「我能复现这个结果」的证据。投入产出的所有判断都从这句话出发。

## 故事四问（准入守门）

一段经历要进案例库，先过四问——对应需求管理里的真需求四要素：

1. **雇主是谁？** 当时的客户、上级、业务方是谁
2. **场景是什么？** 什么背景、什么约束下发生的
3. **痛点是什么？** 不解决会怎样
4. **预期效果是什么？** 做完之后可验证的变化

对每段候选经历逐项追问，最多三轮。三轮仍补不齐四要素的判伪故事，不进库——和需求管理筛伪需求同一套逻辑：说不清效果的经历，讲出来只是流水账。「我负责过很多项目」和「我把月均 3 次生产事故降到 0」是两种反馈，后一种才收。用户补不出数字的，让他回去找：翻聊天记录、翻周报、问当时的同事，找到为止；实在找不到就标注「估算」并写清推算依据。

## 六段骨架

过审的经历按这个骨架成型，也是 FDE 一线实践文章的标准叙事：

1. **场景痛点**：谁在什么场景下被什么卡住
2. **量化诊断**：翻记录、对数据、算比例，用数字定位问题
3. **最小方案**：用最简单的动作先解掉卡点
4. **踩坑**：哪个动作多余、哪次被打回、学到了什么
5. **量化效果**：省了多少、快了多少、成本多少
6. **能力收束**：这件事证明你有什么可迁移的能力

第 2、5 段是硬门槛：缺数字的诊断和缺数字的效果，案例降级为经历描述，不能进面试。第 4 段（踩坑）反而要保留甚至强调——面试官对零瑕疵的故事天然起疑，一个真实的弯路比十句自我表扬更可信。

## 开发测试双线

案例是假设，面试是实验。

- **开发线**：每个案例做三档——90 秒完整版、30 秒电梯版、10 秒一句话版，存进案例库。
- **测试线**：每场面试讲完，24 小时内记 landing 情况：面试官追问了哪段（有引力）、跳过了哪段（没打中）。按反馈改下一版，拒绝凭感觉润色。
- **节奏**：改一版 → 投一轮 / 面一场 → 带数据回来改。先在一个渠道跑通再扩展。想一次做出完美简历再投，和一次性建全系统再汇报，是同一种坑——毕其功于一役在求职里同样难承其重。

## 收敛条件

案例库 3-5 个过审案例，每个有数字、有三档版本，覆盖三类：独立扛事、协作冲突、技术深度。缺哪类补哪类。收敛完 → 推荐面试与离职做模拟面试。

## 终止条件

案例齐了 → 面试与离职。缺数字证据 → 回「简历/JD」做量化自查。经历撑不起案例 → 回「方向诊断」挖可转移技能。
