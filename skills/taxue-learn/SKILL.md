# taxue-learn：学习方法论 + 素材管理 + 连续学习

| 学习不是接收信息，是改变行为。

--------

## 思维根基

- **费曼学习法**：不用术语能解释清楚才算真懂。
- **杜威「做中学」**：不是先学再做，是在做中学。输出倒逼输入。

--------

## 知识库接入

本技能的落盘读写都经过「库根」（vault）。库根在哪，按顺序发现，正文不写死任何人的路径（完整规范见 `../taxue/references/vault.md`，本技能与家族其他件共用一条发现链、一份配置）：

1. **本次对话指定**：用户说了库在哪，就用哪。
2. **环境变量** `TAXUE_VAULT`。
3. **配置文件** `~/.taxue/config.json` 的 `entries`（入口名：`learn_inbox` / `learn_quotes` / `learn_insights` / `learn_atoms` / `learn_topics`）。
4. **常见位置探测**：`~/素材库`、`~/知识库`、当前项目的 `./素材库`。
5. **都没有** → 问用户怎么走，三态选一：
   - **接入已有库**：用户提供位置，五类入口写入配置，以后不再问。
   - **从零新建**：按模板建一套空库，从第一条原子开始攒。
   - **无库轻用**：只学方法论不落素材。学习档案照常（放当前工作区，见「档案落点」），素材管理章节跳过，输出效果不受影响。

**本技能需要的入口**（声明见 vault.md 命名约定，具体路径在用户配置里）：

| 入口 | 语义 | 缺失时 |
|------|------|--------|
| `learn_inbox` | 收件箱 | 建议新建库时一并建 |
| `learn_quotes` | 金句库 | 案例数据从归档检索 |
| `learn_insights` | 洞见库 | 同上 |
| `learn_atoms` | 原子库 atoms.jsonl | 无库轻用 |
| `learn_topics` | 学习课题目录 | 档案落项目内 |

老库目录名不标准的，把五类入口直接指向实际位置写入配置，不改库本身。

**从零新建的模板**：

```text
{vault_root}/
├── 00_收件箱/              # 所有信息先进这里
├── 01_素材库/
│   ├── 金句库.md
│   ├── 洞见库.md
│   ├── 案例库.md
│   └── 数据洞察.md
├── 02_原子库/
│   └── atoms.jsonl         # 知识原子
└── 03_学习课题/
    └── {课题名}/课题档案.md
```

检索纪律对所有布局通用：先 `ls` 看实际文件再 grep，别凭记忆拼路径。

## 四步内化法

### 1. 收件箱 + 知识原子（输入→整理）

效能 > 效率。追求「留住什么」，不追求「看了多少」。

**收件**：所有信息先进收件箱（入口 `inbox`，见知识库接入），3秒判断：噪音删除 / 信号归档 / 模糊的留在收件箱。每周清理，不积压超过7天。

**来源可信度分级**（收件时一并判断，不同等级不同处理策略）：
- **A 类：可核验一手**（论文 / 官方数据 / 实验 / 原著原文）→ 直接入库
- **B 类：权威转述**（白皮书 / 权威机构报告 / 教材）→ 直接入库，标注原始出处
- **C 类：行业推断**（媒体 / 博客 / 专家个人观点 / 二手转述）→ 标「行业推断」再入库，不可当作事实直接使用
- **D 类：未核验声明**（「看起来对」但找不到来源）→ 单独存「待核验区」，不进入主知识库

| C 类素材是学习的起点，不是终点。把它当「假设」而不是「结论」用。

**整理**：不存原文，存最小可复用单元：
- 核心观点（1句话）
- 关键细节（3-5条）
- 适用场景（什么时候用）
- 个人理解（和我的经验关联）
- 来源类别（A/B/C/D 选一）

每个原子必须能回答「什么时候用」，否则是垃圾。

**入库四问**（每个观点必须能回答前两问，第三、四问 B 类以上必答）：
1. 谁说的？什么身份？什么背景？
2. 他说的时候基于什么数据 / 样本 / 论据？
3. 适用范围是什么？什么时候不成立？
4. 至少能列一个「反例」或「竞争性解释」吗？

答不上来的 → 降级到 D 类，进「待核验区」。

### 2. 交互内化（掌握）

| 方法 | 适用场景 | 操作 |
|------|----------|------|
| 苏格拉底追问 | 有个「听起来对」的观点 | 提反例，逼到边界，澄清定义 |
| 案例分析 | 抽象概念需要落地 | 真实场景，问「你会怎么做」 |
| 费曼输出 | 想检验是否真懂 | 用大白话讲一遍，讲不清就是没懂 |

### 3. 输出倒逼输入

**输出形式**：
- 一篇笔记（用自己的话重写）
- 一个分享（讲给别人听）
- 一个应用（用到实际工作/生活）

**输出标准**：
- 不是复制粘贴，是重新组织
- 不是罗列要点，是提炼洞察
- 不是「我学到了」，是「我打算怎么用」

### 4. 定期复盘

每周打开各课题档案做复盘（档案见下节），对着「原子流水」问三件事：
- 哪些原子用上了？（状态改「已用」，usage_count +1）
- 哪些还没用？（状态「未用」，想想卡在哪）
- 哪些被推翻了？（记反例，来源降级）

复盘内容写进档案的「复盘」键下，跨课题的收束写进「下一步」。

## 连续学习档案

学习跨不过一次对话。没有档案，每个课题都从零开始；有档案，接着上次的原子继续。

### 档案落点

- 默认 `{库根}/03_学习课题/{课题名}/课题档案.md`（入口 `topics`）。
- 无库模式：看当前工作区在哪，就在哪建 `{当前工作区}/学习课题/{课题名}/`。
- 当前位置是泛目录（家目录、桌面、下载这类）时，先问用户档案放哪，给一句建议（常用的项目或素材库），不默认撒在原地。
- 用户指定了位置就用用户的。

### 课题档案结构

```markdown
# {课题名}｜课题档案

## 目标

{可检查的能力，不写「了解」「熟悉」——写「能独立算出一只主动基金的费后收益」}

## 原子流水

| 日期 | 原子 | 来源 | 状态 |
|---|---|---|---|
| 10-02 | {一句话} | {书/文章/课} | 未用 |

## 复盘

- 用上了：
- 没看懂：
- 推翻了：

## 下一步

{一句话}
```

「复盘」下的三个键是反馈的唯一入口。写在键后面的才算反馈；模板提示、键名本身都不算。三个键都是空的，就是没有反馈——先问，别自行推进。

### 复盘驱动

| 复盘信号 | 下一步 |
|---|---|
| 用上了 | 状态改「已用」；反复用上的原子升级为素材条目进素材库（补齐来源 + 可信度字段）；课题推进下一层 |
| 没看懂 | 换更具体的例子，降抽象度；不堆新概念 |
| 推翻了 | 原子记入反例，来源可信度降一级；课题转入修正 |
| 没写复盘 | 保持节奏，小步推进；下次先要复盘 |

### 断点续学

- 「继续学 {课题}」：先读档案 → 只看复盘键下用户实际写的内容 → 按上表定下一步。
- 「带我学 {课题}」且没有档案：先问目标（写成可检查的能力），建档案，再开始攒第一批原子。别跳过档案直接开讲。

## 素材管理

最好的素材不是找出来的，是攒出来的。检索与管理一体化，让你的素材库越用越值钱。

**先分流再入库**：为了学会某个东西提取的，走知识原子（四步内化法，进原子库 `atoms.jsonl`）；为了以后创作引用摘录的，走素材条目（本节，进素材库）。同一份材料先成原子；原子反复被用上，再升级为素材。两条轨字段不同，别混。

### 素材类型
| 类型 | 内容 | 适用场景 |
|------|------|----------|
| 金句 | 精炼的、有冲击力的短句 | 标题、开头、结尾、社交媒体 |
| 洞见 | 深度分析的结论 | 文章核心观点、视频脚本 |
| 案例 | 真实经历的案例 | 论证、讲故事 |
| 方法论 | 可复用的思维框架 | 教程、分析文章 |

### 素材入库字段（每条素材必填 4 项）
| 字段 | 说明 |
|------|------|
| 内容 | 金句/洞见/案例 原文 |
| 来源 | 人名 / 书名 / 机构 / URL / 访谈时间 |
| 可信度 | A 可核验一手 / B 权威转述 / C 行业推断 / D 未核验 |
| 核验状态 | 已核验（有原文定位） / 待核验（模糊出处） |

| 金句本身就是主观表达，不需「证伪条件」；证伪只对可核验的事实主张有意义。

### 使用前置门控（每次调用素材时自检）
- 该条素材是否已核验？**未核验的必须加 [****待核验] 标记再输出**
- 属于哪个可信度等级？**C 级必须标「行业推断」**，不可当事实用
- **引用范围不能超过素材本身实际支持的内容**。一句金句不证明整个论点。
- **来源模糊的素材（「某TED演讲」「有人说」）建议不使用**；用了必须标「出处未核验」

### 素材检索流程

固定入口 = 库根下的素材目录（入口 `quotes` / `insights`，无库模式本节跳过）。库里的文件名会变，检索前先 ls 看实际文件，别凭记忆拼路径：

```bash
ls {库根}/01_素材库/
grep -rn "关键词" {库根}/01_素材库/ --include="*.md" | head -20
```

`grep -n` 直接给文件、行号和上下文，命中即用；只列文件名还得再开一轮。案例、数据没有独立文件时，从库内归档目录检索。

## 输出前质量门（强制自查）

1. 有没有给一个今天能做的验证动作？没有 → 补一个。
2. 有没有把「可能」写成「一定」？有 → 改成「待验证」。
3. 有没有只站一个立场？有 → 立场保留，一句话交代它最强的反例或适用边界。补边界，不是和稀泥。
4. 有没有用「综合来看」「各方面」等模糊词？有 → 具体化。

任一不通过，修正后再输出。

## 反模式声明

### 失败 1：存原文不存原子
收藏了一堆文章和截图，用的时候还得重读一遍，等于没整理。
**纠正**：存最小可复用单元——核心观点 + 关键细节 + 适用场景 + 个人理解 + 来源类别。答不出「什么时候用」的就是垃圾。

### 失败 2：C 类素材当结论用
把媒体、博客、专家个人观点里的行业推断，当成事实写进输出。
**纠正**：C 类必须标「行业推断」再入库，只当假设用，不当结论用。

### 失败 3：未核验素材直接输出
来源模糊（「某 TED 演讲」「有人说」「研究表明」）还照用。
**纠正**：加 `[待核验]` 标记再用；出处模糊的建议不用，用了必须标「出处未核验」。

### 失败 4：用输出替代内化
复制粘贴当输出，罗列要点当洞察。
**纠正**：用自己的话重新组织，落到「我打算怎么用」——不是「我学到了」。

### 失败 5：引用范围超过素材本身
拿一句金句去证明整个论点。
**纠正**：引用不得超出该条素材实际支持的内容范围。

### 失败 6：凭记忆拼素材路径
按上次记的文件名打开素材库，文件改过名就扑空，再退去扫全盘。
**纠正**：先 `ls` 固定入口看实际文件，再 grep。

### 失败 7：拿自己的库当别人的库
把某台机器、某个人的目录布局写死进流程，换个人换台机器就失效。
**纠正**：路径走发现链（指定 → 环境变量 → 配置 → 探测），布局差异用 `layout` 映射适配，正文不出现任何具体人名路径。

## DO NOT

- 写内容本身 → `content`（learn 只管方法与素材，创作归 content）
- 一句话看透本质 → `insight`
- 固化流程、做工具 → `build`
- 连续课题不读档案直接开讲 → 先读（或先建）档案
- 库根未确认就猜路径 → 先走发现链，或问用户三态选一

--------

## 共享规则与纪律

本技能继承 `../taxue/references/shared-rules.md` 的通用纪律，冲突时以它为准：**结果优先**（先交付立场与可验证动作，过程只在改变质量时写入）、**证据来源**（结论必须可追到来源，禁止无源断言）、语言与通用 DO NOT。

--------

## Outcome Contract

- **产出**：可复用的知识原子或素材条目（含来源与可信度）；连续课题的课题档案（含复盘与下一步）；需要时的一套新建库或一条接入配置
- **做完的标准**：每条都有来源、可信度等级、适用场景，用户能说出「我打算怎么用」；连续课题能从档案接上上次进度；换台机器换个人，按发现链都能跑通
- **不做的事**：不写内容本身（→ content），不做数据分析本身

## 验收用例

### 用例 1：新课题（无库环境）

用户说：「带我学资产配置。」机器上没有库，用户也没提接入。

必须：
- 先问目标，写成可检查的能力
- 走三态问一句：接入已有库、从零新建、还是先不建库
- 用户选「先不建库」→ 档案建在当前工作区 `学习课题/` 下（泛目录先问放哪），素材功能跳过，方法论输出不受影响

### 用例 2：从零新建

用户说：「帮我建一个个人知识库。」

必须：
- 按模板建目录树（收件箱 / 素材库 / 原子库 / 学习课题）
- 五类入口写入 `~/.taxue/config.json` 的 entries，指向新建位置
- 攒第一条原子时走完整字段（content / source / confidence / when_to_use / usage_count）

### 用例 3：断点续学 + 原子升级

课题档案已有 5 条原子，复盘「用上了」键下写着「第 3 条做了定投分析」。

必须：
- 读档案，第 3 条状态改「已用」，原子库 usage_count +1
- 该原子来源与可信度齐全 → 升级为素材条目（补齐来源 + 可信度 + 核验状态）
- 下一步按复盘驱动表推进，不重复已掌握内容

### 用例 4：复盘为空

档案里「复盘」三个键后面没有内容，只有模板提示。

必须：
- 视为没有反馈
- 先问「上次攒的原子用上了没有」，不自行推进

### 用例 5：老库接入

用户已有旧库，目录名和模板不一致，说「用我的库」。

必须：
- 不改用户库的任何目录名
- 五类入口直接指向实际位置，写入 `~/.taxue/config.json` 的 entries
- 某类入口在旧库里不存在 → 按降级策略处理（归档检索或跳过），不报错不虚构
