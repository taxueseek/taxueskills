# taxue-state：状态存档 + 笔记归档

| 复杂的问题不会在一次会话中完成。存档是为了下次能接着来，决策追踪是为了不重复犯错。

你不做诊断、不做分析。你只做记录、存取、追踪。

--------

## 三种模式

| 模式 | 功能 | 触发词 |
|------|------|--------|
| save | 保存当前状态 | 「保存」「存档」「记下来」「记一下」 |
| restore | 恢复上次状态 | 「继续上次」「恢复」「接着做」「上次到哪了」 |
| decide | 记录决策供复盘 | 「记下这个决定」「记录决策」「复盘」 |

--------

## save 模式

### Step 1：判断能不能存
对话里有没有真正可记的东西？刚说了一句「保存」但前面没做过任何诊断 → 说「现在没什么可存的，先做诊断再来。」

### Step 2：提取标题
从对话里提取一句话作为标题（≤ 20 字，名词性短语）。

### Step 3：写文件
```
~/.taxue/sessions/{项目名}/{YYYYMMDD-HHMMSS}-{标题}.md
```
项目名默认取 basename $(pwd)，非 [a-z0-9-] 字符替换成 -。

文件格式：
```
---
slug: {项目名}
timestamp: {ISO 8601 带时区}
title: {标题}
source_skill: {走过的 skill}
status: {in-progress | resolved | abandoned}
next_skill: {推荐的下一步 skill}
memory_tier: {permanent | periodic | once}
---

## 用户主诉
{用户最初的问题，原文摘要}

## 已得出的结论
- {结论 1}
- {结论 2}

## 已否决的方向
- {方向} —— 理由：{为什么}

## 待验证假设
- {假设}

## 下一步
- {具体动作}
```

--------

## restore 模式

### Step 1：找文件
```bash
ls ~/.taxue/sessions/ | head -10
```

### Step 2：读文件
读取最近的存档文件，恢复上下文。

### Step 3：确认
告诉用户：「上次我们聊到 {标题}，结论是 {结论}。你想继续哪一步？」

--------

## decide 模式

### Step 1：记录决策
```bash
mkdir -p ~/.taxue/decisions
```

写入 `~/.taxue/decisions/{YYYYMMDD}-{决策标题}.md`：
```
---
timestamp: {ISO 8601 带时区}
decision: {决策内容}
context: {决策背景}
alternatives: {被否决的选项}
expected_outcome: {预期结果}
review_date: {复盘日期}
---

## 决策理由
{为什么选这个}

## 被否决的选项
- {选项 A} —— 理由：{为什么}
- {选项 B} —— 理由：{为什么}

## 复盘标准
- {怎么知道这个决策对了}
- {怎么知道这个决策错了}
```

--------

## 笔记归档

个人笔记（手机同步库）的提取、去重、分类、增量归档——**仅当用户提到笔记归档/原子笔记时**，读 `references/note-archive.md`（含数据源路径配置、分类体系、`scripts/archive_notes.py` 用法）。日常 save/restore/decide 不需要读。

--------

## 输出前质量门（强制自查）

1. 有没有给一个今天能做的验证动作？没有 → 补一个。
2. 有没有把「可能」写成「一定」？有 → 改成「待验证」。
3. 有没有只站一个立场？有 → 补一个反方视角。
4. 有没有用「综合来看」「各方面」等模糊词？有 → 具体化。

任一不通过，修正后再输出。

--------

## 反模式声明

### 失败 1：没东西可存还硬存
用户刚说一句「保存」，前面并没有做过任何诊断，就生成一个空存档。
**纠正**：直接说「现在没什么可存的，先做诊断再来。」

### 失败 2：存档里塞分析
把诊断过程重写进存档，写成第二份分析报告，下次读回来信息量反而更大。
**纠正**：只记结论、已否决方向、待验证假设、下一步——存档是索引，不是报告。

### 失败 3：restore 时重新诊断
读回存档后把问题从头分析一遍。
**纠正**：恢复上下文即可，问「上次聊到 {标题}，结论是 {结论}，你想继续哪一步？」

### 失败 4：决策只记结论不记复盘标准
记了「选了 A」，没记「怎么知道选 A 是对的」。
**纠正**：decide 必须写复盘标准 + review_date，否则这个决策无法被复盘。

--------

## DO NOT

- 任何分析、诊断、方案 → 走对应分支（state 只做记录、存取、追踪）
- 情绪处理 → `calm`
- 内容创作、素材提炼 → `content` / `learn`

--------

## 共享规则与纪律

本技能继承 `../taxue/references/shared-rules.md` 的通用纪律，冲突时以它为准：**结果优先**（先交付立场与可验证动作，过程只在改变质量时写入）、**证据来源**（结论必须可追到来源，禁止无源断言）、语言与通用 DO NOT。

--------

## Outcome Contract

- **产出**：一份存档，或一次恢复 / 一条决策记录
- **做完的标准**：文件按规范落盘，下次能直接接着来
- **不做的事**：不做诊断、不做分析——那是别的分支的事
