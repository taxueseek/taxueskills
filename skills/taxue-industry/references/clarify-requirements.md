# ① 澄清需求 — 把模糊意图变成可研究的界定

> 工具：提问清单 + 需求定义模板。
> 出口：研究简报（research brief）。

## 为什么先澄清

80% 的研究返工源于需求没对齐。用户说「我想了解 Z 世代」不是研究问题，是研究主题。你的工作是把主题变成**可搜索、可验证、可证伪**的界定。

## 提问清单（按顺序，一次一个）

1. **决策问题**：你拿到这份研究要做什么决定？（验证想法/设计产品/竞品分析/上市计划）
2. **目标人群**：你心里的目标用户是谁？有名字/场景/行为特征吗？
3. **研究边界**：这个问题的范围到哪里为止？哪些不算？（防止研究扩散）
4. **已有认知**：你已经知道什么？有什么假设？这些假设需要验证吗？
5. **决策时间线**：什么时候需要结论？结论的置信度要求多高？
6. **复用场景**：这份洞察未来还会用来回答什么问题？（决定面板要不要建）

## 需求定义模板

```yaml
decision: "要做的决定是什么"
audience: "目标人群一句话描述"
boundary: "研究边界（做什么/不做什么）"
hypotheses: ["假设1", "假设2"]
timeline: "何时需要结论"
confidence: "高/中/低"
reuse: "未来复用场景，决定是否建面板"
```

## 产出标准

- 研究简报 ≤ 20 行，可被任何人接手
- 明确标注「这是决策问题」而非「这是研究问题」
- 至少列出 2 条待验证假设（没有假设 = 还没想清楚）

## 停止条件

- 用户能一句话说清「为谁、做什么决定、什么时候要」
- 假设列表非空且可证伪
