## 核心原则

1. **假设驱动**：先提假设，再用证据验证，不是搜到什么说什么
2. **标清来源靠不靠谱**：每个发现标注可靠程度（高/中/低），没有来源的结论就是猜
3. **结构优先**：输出认知地图，不是信息清单
4. **够用就停**：L1 不做 L2 的事
5. **对标找「值得模仿的」，不是找最好的**；**传播是结构性的，不是运气**

## 先确认三件事

### 确认深度
| 用户说的 | 走哪层 |
|----------|--------|
| 「快速了解」「概览」「扫一眼」 | L1 概览 |
| 「深度研究」「详细分析」「搞明白」 | L2 深度 |
| 「值不值得做」「能不能进」「能投吗」 | L3 商业判断 |
| 没说深度 | 默认 L1，问一句「要深度研究吗？」 |

### 确认范围
- 时间：当前 / 近3年 / 历史演变？地域：全球 / 中国 / 特定区域？细分：全行业 / 某个赛道？

### 确认输出偏好
- 要数据支撑还是框架优先？要对比分析还是单一深挖？有没有特定问题？

**简洁确认，不过度追问。** 用户给了明确深度就走。

--------

## L1 概览层（~10分钟）

1. web_search 搜索行业基本信息（定义、规模、主要玩家）
2. 补充最新趋势和动态
3. 整合输出「行业名片」

末尾必加来源可信度声明：
> 来源可信度：本层发现来自 {N} 个独立来源。{A} 条来自权威机构/白皮书，{B} 条来自行业推断。数据年份范围 {YYYY-YYYY}。

--------

## L2 深度层（~30分钟）

目标：理解行业结构、竞争格局、底层逻辑。

### Step 1：L1 概览
（作为深度研究基础，同上）

### Step 2：假设树生成
基于概览，生成 3-5 个关键研究问题和竞争假设。

### Step 3：证据收集
针对每个假设，收集支持/反对证据。

### Step 4：认知地图
输出行业认知地图，包含：
- 市场规模与增长
- 竞争格局（主要玩家、差异化）
- 产业链结构
- 关键成功因素
- 风险与机会

--------

## L3 商业判断层

基于 L2 的认知地图，回答：
- 值不值得进？
- 怎么进？
- 预期回报与风险？

## 用户研究

### 双层研究体系

**用户层（理解「为谁而做」）**
7 步闭环，产出用户画像面板（panel_type: user）。

**商业层（回答「值不值得做、怎么赢」）**
4 大问题域，产出商业面板（panel_type: market/competitor/gtm）。

| 商业问题 | 产出资产 | 依赖 |
|----------|----------|------|
| 市场值不值得进 | 市场面板 | 用户面板（需求侧） |
| 谁在竞争、怎么差异化 | 竞品面板 | 用户 + 市场面板 |
| 怎么定价 | 定价洞察 | 用户面板（支付意愿） |
| 怎么上市 | GTM 面板 | 用户 + 竞品 + 市场 |

**核心依赖**：先用户后商业。没有用户面板的商业研究是空中楼阁。

### 7 步工作流（用户层，MECE 穷尽）
① 澄清需求 → ② 规划研究 → ③ 搜索画像 → ④ 扫描社媒 → ⑤ 构建画像 → ⑥ 访谈/小组 → ⑦ 报告+面板

### 关键决策原则
1. **先查面板，再开新研究。** 每次新问题先问：已有面板能不能回答？能就复用，这是资产的价值。
2. **面板是结构化的，不是散文。** 面板必须符合 schema。

### 面板资产与校验

面板落盘在 `~/.taxue/panels/`，`index.json` 是注册表——新问题先查 `index.json`，命中直接复用。

```
panels/
├── {slug}.json              # 用户面板（7 维画像）
├── market-{slug}.json       # 市场面板（TAM/SAM/SOM + verdict）
├── competitors-{slug}.json  # 竞品面板（拆解 + 机会矩阵）
├── gtm-{slug}.json          # 上市面板（北极星 + VP + 渠道）
└── index.json               # 注册表（可检索）
```

校验：`python3 scripts/validate_panel.py ~/.taxue/panels/`，退出码 0 = 通过。面板类型限 `user / market / competitor / gtm`，置信度限 `L1 / L2 / L3`；`--init` 初始化目录，`--self-test` 跑自检。

## 输出前质量门（强制自查）

1. 有没有给一个今天能做的验证动作？没有 → 补一个。
2. 有没有把「可能」写成「一定」？有 → 改成「待验证」。
3. 有没有只站一个立场？有 → 补一个反方视角。
4. 有没有用「综合来看」「各方面」等模糊词？有 → 具体化。

任一不通过，修正后再输出。

## 反模式声明

### 失败 1：跳过澄清直接开搜
用户说「了解用户」就直接开搜，没确认目标人群和决策问题。
**纠正**：先澄清需求（用户层 ①），产出研究简报再动手。

### 失败 2：有面板不查
已有面板能回答，还从头重做一遍研究。
**纠正**：每次先查 `~/.taxue/panels/index.json`，命中直接复用——这是面板存在的意义。

### 失败 3：画像无证据
把研究者的假设写进画像，当成事实交付。
**纠正**：每条属性标注 evidence；无证据的标「推断」+ 低置信度。

### 失败 4：置信度不足强出报告
L1 探索性画像直接给出高置信结论。
**纠正**：关键假设走访谈验证（用户层 ⑥），L2 以上才能发布结论。

## DO NOT

- 商业判断快诊（值不值得做）→ `diagnosis`
- 技术 / 文献深度综述 → `rw-research`
- 投资分析 → `invest` 系列
- 不做无来源断言：画像每条属性必须有证据
- 不跳过面板复用：先查 `index.json`，命中直接复用

--------

## 共享规则与纪律

本技能继承 `../taxue/references/shared-rules.md` 的通用纪律，冲突时以它为准：**结果优先**（先交付立场与可验证动作，过程只在改变质量时写入）、**证据来源**（结论必须可追到来源，禁止无源断言）、语言与通用 DO NOT。

--------

## Outcome Contract

- **产出**：认知地图 / 用户画像面板 / 商业面板（可复用资产）
- **做完的标准**：结论都有来源与可靠度标注，面板符合 schema 且已落盘
- **不做的事**：不做商业判断快诊（→ diagnosis），不做技术文献综述
