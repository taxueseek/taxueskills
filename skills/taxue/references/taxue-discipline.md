# taxue-discipline：论证纪律速查表

> 公共参考文件，由推理类 taxue Skill 统一引用（industry / insight / learn / solve / content）。**不重复维护**。
> 本表只处理「推理类」输出的论证纪律，不涉情绪处理、写作手法、语言风格——那些在各 Skill 内部自行定义。

---

## 一、证据纪律六条

1. **四区分离**：四类信息来源必须分开保存和使用——
   - 用户提供的事实 / 经历
   - 公开可核验来源（论文 / 官方数据 / 原著原文）
   - 当前推断（我的推导）
   - 未知事项（还没核实的缺口）
   - 四类信息不能混存混用，不能用「推断」替代「事实」输出。

2. **摘要只能支持摘要中明确报告的内容**：不能替代全文证据。读摘要就只引用摘要里实际写了的。

3. **来源可信度四级**：
   - **A 可核验一手**：论文 / 官方数据 / 实验 / 原著原文 → 可直接入库 / 引用
   - **B 权威转述**：白皮书 / 权威机构报告 / 教材 → 引用时标注原始出处
   - **C 行业推断**：媒体 / 博客 / 专家个人观点 / 二手转述 → 标「行业推断」再使用，不可当事实
   - **D 未核验声明**：模糊出处 / 个人随想 → 单独存「待核验区」，不进主知识库
   - **执行纪律**：A/B 可以直接引用；C 必须标「行业推断」；D 不进主知识库。

4. **核验纪律**：
   - 不生成不存在的论文 / 数据 / DOI / 案例 / 报告
   - 核验版本 / 费用 / 政策时，回到当前官方页面 + 标注核验日期
   - 无法核验基本出处的信息，不进正式清单，只能进「待核验区」

5. **证伪条件先行**：给出任何答案之前，先问自己「何种观察/证据会改变这个答案」。列得出来才能输出；列不出来降级为「个人观察」。

6. **证据确定性是结果层判断，不是给整篇文章贴分数**。断言的质量看其证据链强度，不是作者有多少篇引用。

## 二、可证伪与停止条件

### 可证伪性要求
- 每个事实性断言必须能回答：**「什么观察/证据会让我收回这句话？」**
- 答不上来 = 是修辞，不是判断
- 「事实判断」「价值判断」「推断」三类输出必须显式分离——不能用价值伪装成事实

### 停止条件（上下文感知 v2）：信息的充足度 × 问题的开放度

先快速判断两维度矩阵：

```
            问题开放度高             问题开放度高
            （要不要/该不该）        （为什么/是否如此）
信息充足    直接给结论+替代视角     直接给解释+证据强度标
信息不足    直接给结论+假设标       先澄清清单再给判断

            问题开放度低             问题开放度低
            （如何做/怎么配置）      （查数据/列信息）
信息充足    直接给操作步骤          直接给数据+来源
信息不足    直接给通用步骤+风险标   直接给数据+待补项标
```

**3 条硬规则（防止误停 + 防止武断）：**

- **用户已给「URL + 具体疑问」→ 不触发停止**。直接回答，不假澄清（盲区 #2 修复）
- **数据超过 3 个月的市场/行业数据 → 标注时效性警示**，但不因此停止输出（盲区 #5 修复）
- **用户未定义目标 / 未列约束条件（如：想赚钱但没说基数/周期/风险偏好）→ 必须停下追问**；这是真缺失，不是假澄清

## 三、替代解释与反例（场景化版）

**适用范围**：仅**论证密集型场景**需要替代解释或反例。

### 论证密集型场景（必须至少 1 个替代结论或反例）
- 行业研究（taxue-industry）
- 本质洞察（taxue-insight）
- 决策求解（taxue-solve）
- 商业判断（taxue-diagnosis）
- 深度研究（argo research / rw-research）

### 操作场景（不需要替代解释，避免噪音）
- 工具配置 / 代码报错 / 操作步骤 / 数据查询
- 用户给了具体 URL / 具体数据的具体问题

### 操作规则
- **论证密集型场景**：不能只给单一归因——必须补充「另一种可能」或「反向前提」
- **任何论证密集型断言**：必须列至少 1 个反例 / 边界条件 / 失效场景
- **操作场景**：聚焦给正确答案，不强行展开替代方案
- **替代质量门槛**：替代方案必须与原方案在同一维度上有明确差异点（如：不同时间视角 / 不同人群 / 不同风险偏好）。列了但只换包装不算替代（防止假替代噪声）

## 四、场景化规则快速判断

回答任何问题前先问自己：**用户在问什么类型的问题？**

```
问题类型判断流程：
│
├─ 用户在问「怎么配置 / 怎么做 / 报错怎么办」
│  → 操作问题 → 直接给步骤，不套论证纪律
│
├─ 用户在问「为什么这样 / 本质是什么 / 规律是什么」
│  → 解释问题 → 给证据 + 区分事实/推断/未知事项
│
├─ 用户在问「要不要 / 该不该 / 值不值得」
│  → 决策问题 → 给替代视角 + 论证强度标签 + 反例
│
└─ 用户在给了一段材料 / 信息，想「看看这个」
   → 校验问题 → 证据分级 + 可信度标注 + 缺口清单
```

## 五、事实 / 价值 / 推断 标签执行

| 输出类型 | 标识方式 | 示例 |
|---------|---------|------|
| 事实判断 | 有原文定位 + 核验日期 | 「据 XX 报告（链接, 2026-01-15）市场规模为 N 亿」 |
| 推断判断 | 标注「基于 {事实} 的推断」 | 「基于近 3 年数据推断，趋势走向是 X」 |
| 价值判断 | 标注「情景区」「个人立场」 | 「对我这种厌恶风险的人来说，这条路不合适」 |

> 三类混同 = 用「好不好」伪装成「是什么」，是最常见的认知陷阱。

---

## 六、日期与来源的时效纪律

- **所有市场数据 / 行业数据 / 政策数据**标注「年-月」，不写「最近」「最新」等模糊词
- **超过 3 个月的数据**标注「{年-月}（已过 X 个月，或有更新风险）」
- **公开来源摘要**只对内使用，不对外公开发布
- **需要版本/费用/政策/现状时** → 回到官方页面核验
- **API 失败/限流/覆盖不足时** → 切换人工检索，不编造结果
- **工具只是执行手段，不能替代研究判断**
